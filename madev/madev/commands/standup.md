master 에이전트를 실행해 아침 스탠드업을 진행하라.

사용자의 특별 지시사항: $ARGUMENTS
(비어 있으면 통상 업무 기준으로 진행)

마스터에게 전달할 지시:

1. **현황 파악**: 최근 변경 사항(git log가 있으면 확인), `docs/plans/`의 미완료 계획, 이전 스탠드업 보고서(`docs/standup/` 최신 파일), 진행 중인 작업(`work/*/task.md` 중 status: in_progress).

2. **업무 분배**: 오늘 **실제로 필요한 팀만** 가동하라(모든 팀을 무조건 돌리지 말 것). 통상 아침 루틴:
   - seo: 사이트 노출/색인 상태 점검
   - planner: 오늘 발행할 콘텐츠 주제 확정
   - writer: 확정된 주제로 글 작성
   - marketer: 어제 발행물의 홍보 계획
   - developer: seo/cs가 올린 기술 이슈 수정
   - cs: 누적된 피드백 정리 (있는 경우)
   정기 스탠드업의 통상 1라운드 루틴은 **기본 승인된 것으로 본다**(가동할 팀·이유는 보고에 한 줄로 남긴다). 통상 범위를 벗어나 팀을 크게 늘리거나 배포·비용 큰 작업을 붙일 때만 사용자 동의를 받는다.
   - **외부 백엔드 호출은 이 명령을 실행 중인 오케스트레이터 세션(=master 역할)이 직접** 한다: 개발·CS는 codex(`mcp__codex__codex`), 디자인·콘텐츠는 gemini(`bash "${CLAUDE_PLUGIN_ROOT}/adapters/gemini.sh"` — 반드시 `bash`로)를 부서 서브에이전트가 아니라 네가 직접 부른다(더 깊은 레벨로 내리지 마라 — 중첩 위임은 도구·env 접근 불가로 실패). 부서 spawn보다 먼저 외부를 시도하고, 관측 가능한 실패(도구·명령 부재/exit≠0/timeout/빈응답/거부) 시에만 Claude 부서로 폴백.

3. **검수**: 각 팀의 결과물을 검수 규칙에 따라 직접 열어 확인하라. 증거 없는 완료 보고는 미확인으로 처리하라.

4. **보고서 저장**: 최종 보고를 `docs/standup/YYYY-MM-DD.md`로 저장하고 (폴더 없으면 생성), 사용자에게 요약을 보고하라. 구조: ✅ 완료(증거 포함) / ⚠️ 미확인 / ❌ 실패·보류 / 📋 내일 할 일 제안.
