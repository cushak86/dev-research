argument-hint: "[감사 대상 (예: 최근 스탠드업, 특정 파일/작업)]"
---

허위 완료 보고를 잡아내는 감사를 수행하라. 감사자는 피감사자와 분리한다(master가 하지 않는다).

감사 대상: $ARGUMENTS (비어 있으면 가장 최근 `docs/standup/` 보고서)

**감사자 선택 (독립성 우선순위)**:
- **codex(MCP)가 연결돼 있으면 그것으로 독립 감사한다** — 다른 벤더라 같은 계열이 공유하는 맹점까지 잡는다. `mcp__codex__codex`를 `sandbox: read-only`로 호출하고 아래 절차를 지시서로 전달한다.
- codex가 없으면(미설치·미연결) **inspector 에이전트**로 수행한다(Claude 폴백). **폴백 시 감사 결과 첫머리에 반드시 다음을 명시한다: "주의: Codex 독립 감사가 실행되지 않았으며, Claude inspector 폴백 결과임(이종 교차검증 아님)."** 조용히 넘어가지 마라 — 사용자가 이종 검증으로 착각하면 안 된다.

감사자(codex 또는 inspector)에게 전달할 지시:

1. 대상 보고서에서 "완료(✅)"로 표기된 모든 항목을 추출하라.

2. 항목마다 독립적으로 재검증하라:
   - **파일 산출물**: 실제로 존재하는가? 내용이 보고와 일치하는가? 빈 파일이나 껍데기가 아닌가?
   - **코드 변경**: 해당 변경이 실제 코드에 있는가? 빌드가 통과하는가?
   - **발행/배포**: 실제 반영 여부를 확인할 수 있는가? (확인 불가면 불가라고 기록)

3. 판정 기준:
   - ✅ 검증됨 — 증거 확인
   - 🚨 허위 — 완료라고 했으나 결과물이 없거나 내용이 다름
   - ⚠️ 검증 불가 — 로컬에서 확인할 수단이 없음

4. 감사 결과를 `docs/reports/YYYY-MM-DD-audit.md`로 저장하고 요약을 보고하라. 🚨 허위가 발견되면 어떤 항목이 왜 허위인지, 재작업 지시서 초안까지 작성하라.
