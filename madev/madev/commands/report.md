master 에이전트를 실행해 증거 기반 업무 보고서를 작성하라.

보고 범위: $ARGUMENTS (비어 있으면 오늘 하루)

마스터에게 전달할 지시:

1. 보고 범위에 해당하는 작업 흔적을 수집하라: `docs/standup/`·`docs/reports/` 보고서, git 이력(있으면), 진행 중 작업의 `work/*/log.md`, `docs/` 아래 각 팀 산출물의 파일 수정 시각.

2. **검수 규칙을 적용해 재검증하라**:
   - 완료로 기록된 항목마다 결과물을 직접 열어 실제로 존재하고 내용이 맞는지 확인
   - 코드 변경은 빌드/테스트가 실제로 통과하는지 확인
   - 증거를 확인한 것만 ✅, 확인 못 한 것은 ⚠️ 미확인으로 분류

3. 보고서를 `docs/reports/YYYY-MM-DD-report.md`로 저장하고 (폴더 없으면 생성), 사용자에게 다음 구조로 요약하라:
   - 한 줄 총평
   - ✅ 완료 (항목별 증거: 파일 경로 + 핵심 내용 한 줄)
   - ⚠️ 미확인 (이유 포함)
   - ❌ 실패/보류 (원인 + 다음 조치)
   - 📈 수치가 있으면 수치로 (발행 글 수, 수정 파일 수, 해결 이슈 수)

4. **축적**: 이번 작업에서 다음에도 재사용할 교훈이 있으면 `work/learnings.md`에 한 줄로 append하라(일회성·특정작업 한정 내용은 적지 않는다).
