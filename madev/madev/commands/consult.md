외부 이종(異種) 백엔드 워커에게 자문을 요청하라. 이들은 회사 상주 직원(Claude)과 **다른 벤더**라, 같은 계열이 공유하는 맹점을 잡는다. 미설치·미연결이면 Claude로 폴백한다(fail-open — 회사 운영을 막지 않는다).

요청: $ARGUMENTS

## 1. 대상 백엔드 판단 (명시 시에만 외부 호출 — 비용 통제)

**요청 앞머리에 codex/gemini가 명시된 경우에만** 해당 외부 백엔드를 호출한다. 명시가 없으면 Claude 내부(담당 부서/inspector)로 수행한다. 예외: 사용자가 "외부 자문·제3자 검토·독립 감사"를 명시적으로 요청했으면 성격에 맞는 백엔드를 골라도 된다 — 어느 쪽이든 외부 호출은 타사 비용이 드는 행동이다.

- **codex** (OpenAI) — 보조 구현, 코드베이스 분석, 테스트 작성, 로컬 CLI 검증, **독립 감사**.
  - `mcp__codex__codex` MCP 도구로 호출한다(플러그인에 `.mcp.json`으로 번들됨).
  - 감사·검토면 `sandbox: read-only`, 구현이면 `sandbox: workspace-write` + 대상 폴더를 `cwd`로.
  - MCP가 연결 안 돼 있으면(codex 미설치) → 폴백(§3).
- **gemini** (Google) — 제3자 시각 검토, 이미지/스크린샷/다이어그램 분석, 장문 문서 스캔.
  - `bash "${CLAUDE_PLUGIN_ROOT}/adapters/gemini.sh" "<프롬프트>"` 로 호출한다(반드시 `bash`로 — 실행권한 의존 제거).
  - **검토 대상은 프롬프트에 인라인**하라 — 파일·디렉토리 순회를 시키면 헤드리스가 타임아웃한다(단일 이미지/PDF 경로 참조는 예외).
  - 어댑터가 exit 3(agy 미설치)이면 → 폴백(§3).

## 2. 지시서

대상 백엔드에 목표·검토 관점·결과물 형태·완료 기준을 담은 지시를 전달한다. 감사면 "완료로 표기된 항목을 증거로 재검증하고 ✅/⚠️/🚨로 판정"을 명시한다.

## 3. 폴백 (fail-open)

해당 백엔드가 없으면 그 사실을 사용자에게 한 줄로 알리고, **Claude로 대체 수행**한다 — 감사는 `inspector` 에이전트, 구현·분석은 담당 부서(developer 등). 폴백했다는 사실을 결과에 명시한다.

## 4. 결과 처리

- **외부 백엔드는 산출 텍스트만 반환한다. 저장과 log 기록은 호출측(너, Claude)이 수행한다** (감사는 read-only라 외부가 쓰지 못한다).
- 외부 결과는 `[codex 검토 결과]` / `[gemini 검토 결과]` 헤더 아래 **원문 인용**으로 제시한다 — Claude 문장으로 재포장해 뉘앙스를 왜곡하지 마라. 너의 평가는 그 아래 별도로.
- 회사 검수 규칙대로 **증거와 함께** 취합한다(외부의 "완료" 주장도 확인). 작업폴더가 있으면 `work/<작업>/results/<백엔드>.md`에 저장하고 `log.md`에 `[가동] <백엔드> …`로 경로와 함께 남긴다.
