# 증거 기반 보고 (Evidence Report)

AI 직원은 일이 끝나지 않아도 완료했다고 보고하는 경향이 있다. 이 스킬은 그 사고를 막는 검수 절차다.

## 두 가지 절대 규칙

1. **결과물을 직접 열어 확인하고 증거를 보여줄 것.**
   - 파일 산출물 → Read로 열어 내용 확인, 핵심 부분 발췌를 증거로 첨부
   - 코드 변경 → 빌드/테스트 실행, 실제 출력 로그를 증거로 첨부
   - 웹/배포 → 실제 응답 확인, 확인한 URL과 결과를 증거로 첨부
2. **확인하지 못한 것은 못했다고 솔직하게 말할 것.**
   - 검증 수단이 없으면 "완료"가 아니라 "⚠️ 미확인 (사유: ...)"으로 표기
   - 하위 에이전트의 "완료했습니다"는 증거가 아니다 — 주장일 뿐이다

## 검수 절차

1. 완료 주장 목록을 만든다 (누가 무엇을 완료했다고 했는가)
2. 항목마다 검증 방법을 정한다 (열어보기 / 실행하기 / 조회하기)
3. 실제로 검증한다 — 검증을 건너뛴 항목은 자동으로 "미확인"
4. 분류한다: ✅ 완료(증거 포함) / ⚠️ 미확인 / ❌ 실패

## 보고 형식

```
## ✅ 완료 (증거 확인)
- <항목>: <증거 — 파일 경로, 실행 로그 요약, 발췌 내용>

## ⚠️ 미확인
- <항목>: 완료 보고는 있으나 <사유>로 검증하지 못함

## ❌ 실패/보류
- <항목>: <원인> → <다음 조치>
```

빈 섹션도 "없음"으로 명시한다. 미확인을 완료에 섞는 것은 규칙 위반이다.

## 더 강한 검증이 필요할 때
중요한 작업은 여기서 멈추지 말고 `/madev:audit`으로 **감사팀(inspector)**에게 독립 재검사를 맡긴다 (감사자↔피감사자 분리). 작업을 한 팀이 스스로 통과시키지 않게 하는 마지막 게이트다.
