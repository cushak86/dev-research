# MAdev 인헨스 분석 — 현황·버그·개선 방향 (v1.3.0 기준)

> 목적: `claude/madev-enhance-*` 계열에서 개발할 인헨스(v1.4+) 버전의 방향을 도출한다.
> 방법: 플러그인 전체 소스(9 agents · 8 commands · 2 skills · 2 adapters · 템플릿·문서) 통독 + `claude plugin validate` + 어댑터 실행 실측.
> 방침: main 병합 금지 · patch 브랜치 유지.
>
> **구현 상태(이 브랜치, v1.4.0)**: E1(어댑터 권한)·E2(규율 훅)·E3(로그 헬퍼)·E6(업종 프리셋) **반영 완료**. `claude plugin validate --strict` 통과. 나머지(E4·E5·E7~E10)는 후속 로드맵.

## 1. 현황 (Current State)

- **버전**: v1.3.0 (marketplace.json · plugin.json 일치, `claude plugin validate` 통과)
- **구성**
  - **에이전트 9종** (전부 `model: opus`): master(xhigh)·inspector(xhigh) + 부서 7종(planner·designer·developer·cs·marketer·seo·writer, effort high)
  - **명령 8종**: setup · standup · assign · resume · report · audit · consult · hire
  - **스킬 2종**: evidence-report(3중 증거검수) · work-memory(작업폴더 기억·세션재개)
  - **어댑터 2종**: notify.sh(Discord, SSRF·코드실행 방지 하드닝) · gemini.sh(agy, stdin 전달)
  - **MCP 번들**: `.mcp.json`에 codex stdio 서버(`command: codex`)
- **핵심 설계 (이종 백엔드 · worker 모델)**
  - 지휘·검증·전략(master·inspector·planner·marketer·seo) = **Claude opus**
  - 개발·CS = **codex(OpenAI)** / 디자인·콘텐츠 = **gemini(Google)**
  - **외부 호출은 오케스트레이터 최상위(명령/master)가 직접** — 부서 서브에이전트로 내리지 않음(중첩 위임은 MCP·Bash·`CLAUDE_PLUGIN_ROOT` 접근 불가로 런타임 실패). ROADMAP v1.3.0에서 이관 완료.
  - 미설치·실패 시 Claude 부서(opus)로 **fail-open 폴백**.

### 강점 (유지할 자산)
- **보안 하드닝**: notify.sh가 `. source` 금지(literal 파싱)·https discord 웹훅 화이트리스트(SSRF 방지)·페이로드 파일 전달(UTF-8 깨짐 방지). 데모 어댑터치고 견고.
- **fail-open 규율 일관성**: 외부 백엔드/알림 미설치가 회사 운영을 막지 않음.
- **증거 기반 보고**: "하위 에이전트의 '완료'는 주장일 뿐 증거가 아니다"를 스킬·에이전트·명령 전반에 일관 반영. 감사자↔피감사자 분리.
- **worker 모델 정합성**: 중첩 위임 금지를 실측 근거와 함께 명문화(ROADMAP에 회귀 이력까지 기록).
- **문서 품질**: README·GUIDE·ROADMAP·manual·index.html + ROADMAP에 버전별 의사결정 근거 축적.

## 2. 버그 · 문제점 (Bugs / Problems)

### 🔴 HIGH

**B1. 어댑터 실행 권한 없음 → gemini 백엔드 경로가 항상 죽어있음** *(실측 확인)*
- `git ls-files --stage`: `madev/adapters/gemini.sh`·`notify.sh`가 **`100644`(비실행)**.
- 그런데 master.md·consult.md·standup.md·assign.md은 `${CLAUDE_PLUGIN_ROOT}/adapters/gemini.sh "<프롬프트>"`를 **직접 실행**하도록 지시.
- 실측: `./madev/adapters/gemini.sh "test"` → `Permission denied`.
- 결과: 디자인·콘텐츠(gemini) 외부 백엔드가 **clone 직후 항상 permission 오류로 폴백** — 이종 백엔드 절반이 사실상 미작동. (agy가 설치돼 있어도 스크립트 자체가 실행 불가.)
- 수정: `git update-index --chmod=+x`로 `100755` 커밋 + 명령 지시에 `bash <path>` 폴백 병기.

### 🟠 MED

**B2. 규율이 "프롬프트에 쓰여있음"에 의존 — 강제(hook)가 없음**
- 가동 게이트·3중 검수·work-memory·로그 append가 전부 **에이전트 자율 준수**. ROADMAP도 "규율이 쓰여있음과 항상 실행됨 사이 간극"을 자인.
- master가 게이트를 건너뛰거나 log 계측을 누락해도 이를 막는 장치가 없음.

**B3. 로그 계측 수기 → 누락 필연**
- `[가동] developer 완료 | model=codex outcome=검수통과 rework=0`을 매번 손으로 남기게 함. gemini·critic 공통 지적(ROADMAP P1-1). "값 없으면 n/a" 폴백은 있으나 데이터 신뢰도가 낮아짐.

**B4. setup의 settings.json 병합이 자연어 지시(수기 JSON 편집)**
- "env 항목만 병합, 나머지 보존"을 자연어로 지시 → 기존 파일 파싱/보존 실패·덮어쓰기 위험. 프로그램적 병합(jq/스크립트) 아님.
- 더해 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`은 **실험 플래그** — 버전 의존적이고 미래 호환 불투명. 서브에이전트 팀 가동의 전제라 실패 시 회사 전체가 조용히 반쪽 동작할 수 있음.

**B5. codex MCP 가용성 진단이 여러 파일에 분산**
- `mcp__codex__codex`는 deferred(MCP 미연결 시 미노출). master·developer·cs·consult·audit body에 "안 보이면 로드/검색 후 호출, 그래도 없으면 폴백" 지시가 흩어져 있어 유지보수·일관성이 취약. (설계상 fail-open은 맞음.)

### 🟡 LOW

- **B6. 용어 혼용**: `미확인 / 확인 불가 / 검증 불가`, `검수통과 / 검증됨`, `허위 / 실패`가 문서 간 혼용(ROADMAP P2-4).
- **B7. audit 기본 대상 편향**: 기본값이 최근 스탠드업 보고서에 치우침 — `work/*/log.md`·`docs/reports/` 전수성 부족(ROADMAP P2-3).
- **B8. Windows UX 갭**: bash 전용 어댑터, README/GUIDE의 `D:\agents\sync\MAdev` 경로 예시. PowerShell 경로 부재.
- **B9. CLAUDE.company.md 도메인 하드코딩**: "부업 사이트·광고 수익·글 발행"으로 업종 고정(§1·§13). 다른 업종(커머스·SaaS·앱)엔 매번 수기 재작성. 프리셋/대화형 온보딩 없음.
- **B10. hire 모델 안내 불일치**: 신규 에이전트에 haiku/sonnet/opus 선택을 제시하지만 회사 표준은 전부 opus — 일관성 가이드 부재.

## 3. 개선 방향 (Enhancement Directions — v1.4 후보)

우선순위: **P0 즉시수정 → P1 규율강제/자동화 → P2 견고화/온보딩 → P3 관측성/생태계**

### P0 — 즉시 수정 (버그)
- **E1. 어댑터 실행권한 + 호출 견고화** (B1): `chmod +x` 커밋(100755), 명령/master 지시에 `bash "<path>"` 폴백과 `${CLAUDE_PLUGIN_ROOT}` 미해결 대비 절대경로 우회 명문화.

### P1 — 규율을 자율준수에서 강제·자동으로
- **E2. 규율의 hook 강제** (B2, ROADMAP "규율을 도구 레벨로"): Claude Code hooks로
  - PreToolUse: 다중팀 spawn 전 게이트 승인 마커(`log.md`의 `[승인]`) 미존재 시 차단/경고
  - Stop: 완료 보고 전 evidence-report 미적용 감지 경고
  - PostToolUse: 팀 가동 시 log append 유도
  - *실측 후 단계적 도입* — 훅 강제 수준 검증 선행.
- **E3. `/madev:log` 경량 명령 + 표준 로그 헬퍼** (B3, ROADMAP P1-1): 표준 형식 한 줄 append로 계측 누락 방지.
- **E4. 위임 패킷 표준화 스킬** (ROADMAP P1-2): 목표·읽을파일·할일·결과물형태·완료기준·산출경로 고정 구조 강제.

### P2 — 견고화 · 온보딩
- **E5. setup 프로그램적 견고화** (B4): settings.json 병합을 스크립트(jq)로, agent-teams 플래그 상태 점검·안내, codex/agy PATH 자동 진단 리포트.
- **E6. 업종 프리셋 · 대화형 온보딩** (B9): CLAUDE.company.md의 도메인 고정 해소 — 블로그/커머스/SaaS 프리셋 or setup 대화형 채움(§1·§14 자동 인터뷰).
- **E7. 용어 사전 통일 + audit 대상 확장** (B6·B7, ROADMAP P2): 단일 용어 사전 + audit이 work/·reports/ 전수 탐색.

### P3 — 관측성 · 생태계
- **E8. 운영 관측 리포트**: `work/*/log.md`를 집계해 팀별 rework·모델(codex/gemini/opus) 효율·게이트 준수율을 요약(`/madev:report`에 통계 섹션 or 정적 대시보드).
- **E9. 플러그인 자체 테스트/CI**: 명령 frontmatter·마켓플레이스 스키마·어댑터 스모크(권한·fail-open)·버전 일치 자동 검증(현재 자동 테스트 전무 — B1이 그래서 새어나감).
- **E10. Windows 지원** (B8): PowerShell 알림 어댑터 or 문서 정리.

## 4. 개성(정체성) 방향 — 무엇으로 차별화할 것인가

madev의 고유성은 "AI 팀"이 아니라 **규율(discipline)과 이종 백엔드**다. 인헨스는 이 개성을 더 날카롭게:

- **"거짓말 안 하는 회사"** — 증거 기반·적대적 감사·이종 교차검증이 최대 차별점. E2(hook 강제)·E8(감사 관측)으로 *실측 가능한 신뢰*로 밀어붙인다.
- **"진짜 이종 백엔드"** — opus 지휘 + codex 개발 + gemini 디자인의 3-벤더 조합은 흔치 않음. 단 B1로 절반이 죽어있으니 **E1이 개성의 전제**. 살린 뒤 E8로 "어느 벤더가 어느 일을 잘했나"를 데이터로 보여주면 madev만의 서사가 된다.
- **"규율을 코드로"** — 프롬프트 규율에서 hook 강제(E2)로 넘어가면 "말뿐인 AI 팀"과 근본적으로 갈린다. 이게 v1.4의 헤드라인 후보.

## 5. 권고 착수 순서

1. **E1 (P0)** — 어댑터 권한. 개성의 전제이자 확정 버그. 즉시.
2. **E2 or E3 (P1)** — 규율 강제(hook)가 헤드라인, 또는 저비용 확실한 E3(로그 명령)부터.
3. **E6 (P2)** — 온보딩/프리셋으로 초심자 진입장벽 완화.

세부 구현은 사용자와 우선순위 합의 후 팀(예: developer=codex, 없으면 opus)에 분배.
