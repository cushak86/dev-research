Art. 1

가치 — 왜 madev인가

일반적인 "AI 팀" 플러그인은 셋에서 무너진다. madev는 각각에 물리적 장치로 답한다.

문제 01

허위 완료 보고

하위 에이전트가 일이 안 끝나도 "완료했습니다"라고 한다. 증거 없는 성공 주장이 쌓인다.

문제 02

맥락 유실

세션이 끊기면 무엇을 하던 중이었는지 사라진다. 다음 날 처음부터 다시.

문제 03

비용 남발

요청마다 전 팀을 다 돌린다. 필요 없는 팬아웃으로 토큰이 샌다.

madev의 답 — 역할극에 규율을 얹는다

  • 3중 증거검수 + 분리된 감사팀 → 허위 보고를 잡는다. "완료"는 증거로만 인정.
  • 작업폴더(파일 기억) + 세션 재개 → 세션이 끊겨도 중단 지점부터 이어간다.
  • 업무분배 라우팅 + 가동 게이트 → 필요한 팀만 최소로, 비용 큰 작업은 동의 후.
승인 게이트와 작업 폴더(기억)라는 물리적 제약을 건 것은 매우 실질적이고 높은 차별화 가치를 지닌다 — 규칙이 프롬프트 문구가 아니라 절차와 파일로 존재한다. — 제3자 설계 검토 (madev v1.0.0 구축 리뷰)

Art. 3

정책 — 회사 운영 규율

madev의 핵심. 모두 회사 매뉴얼(CLAUDE.md)·스킬·명령에 내장되어, 프롬프트 문구가 아니라 절차로 강제된다.

업무분배 라우팅

필요한 팀만 최소로 가동한다. 전 팀 기본 가동 금지. 판단이 어려우면 master부터, 단일 팀으로 부족할 때만 확장.

가동 게이트 (비용)

2개 팀 이상이거나 긴 작업 전, 어느 팀을 왜 돌릴지 한 줄로 알리고 동의를 받는다. 한 팀짜리 간단한 일은 바로. 예외: 정기 스탠드업 통상 루틴은 기본 승인.

3중 증거검수 (절대 원칙)

① 결과물을 직접 열어 증거를 보고에 첨부. ② 확인 못 한 것은 완료가 아니라 ⚠️ 미확인. ③ 중요한 작업은 감사팀(inspector)이 독립 재검증.

작업폴더 = 회사의 기억

다단계 작업은 work/<작업>/에 task.md·context.md·log.md·results/<팀>.md로 기억한다. context.md에 이력을 쌓지 않는다 — 그건 log의 역할.

운영 로그 (append-only)

고치거나 지우지 않는다. 태그 6종만. 팀 가동에 계측을 붙여 — 어느 팀·모델이 재작업이 잦았는지 데이터로 튜닝한다.

세션 재개 (재진입)

읽기 전 행동 금지. task → context → log → 마지막 산출물 순으로 재정박. status와 log가 어긋나면 log(정본)를 믿는다. 중단 지점부터, 처음부터 다시 하지 않는다.

fail-open

Discord 알림 등 선택 연동은 설정이 없으면 조용히 스킵. 회사 운영을 막지 않는다.

배포 승인

프로덕션 반영(라이브)은 되돌리기 어렵다 → 명시적 승인 후에만. 기본 배포는 git push origin main.

배포 · 버전 정책

로컬 폴더 또는 git 저장소를 marketplace로 등록해 배포. 수정 시 plugin.json·marketplace.json의 version을 함께 올린다.

✅ 검증됨 — 증거 확인 ⚠️ 미확인 · 검증불가 🚨 허위 — 결과물 없음·불일치
[가동] developer 완료 → results/developer.md | model=codex outcome=검수통과 rework=0

모델 배정 가이드 — 이종 백엔드 · worker 모델

각 역할을 맞는 벤더에 배정한다: 지휘·검증·전략은 Claude opus(오판이 회사 전체를 흔드는 자리), 구현은 코드에 강한 codex(GPT), 창작은 gemini — 벤더를 나눠 같은 계열의 맹점을 서로 잡는다. 개발·CS·디자인·콘텐츠는 master(오케스트레이터)가 codex/gemini를 직접 호출해 처리하고, 미설치·미작동이면 Claude(opus) 폴백. v1.3.0 worker 모델: 서브에이전트는 Claude만 가능하고, 게다가 부서 서브에이전트가 외부를 직접 부르면 플러그인 MCP·Bash·CLAUDE_PLUGIN_ROOT 접근 불가로 런타임 실패한다(v1.2.x에서 codex/agy 미사용 원인) → 외부 호출을 오케스트레이터 최상위로 올려 부서 spawn보다 먼저 시도하고, 관측 가능한 실패 시에만 Claude 폴백.

⚠ 창작팀 함정 — rework 지표는 검증 가능한 실패(빌드 깨짐·파일 없음)만 잡는다. 후킹 문구·문장 품질·디자인 감각의 조용한 저하는 지표에 잡히지 않는다(검수를 통과해도 CTR·가독성 하락). 그래서 창작(designer·writer)은 gemini 최상위를 유지한다. 튜닝은 [가동] … rework=N(2~4주)으로 — rework 잦은 부서는 강도↑(Claude effort↑·외부 상위 모델), 기계 검증되는 산출물은 비용↓.

간단한 일

담당 팀을 바로 지목

"seo한테 사이트 노출 점검시켜줘." 게이트 없이 즉시 처리된다.

  • 담당 부서 1명 가동
  • 결과를 증거로 확인
복잡한 일 — 핵심

/madev:assign

마스터가 작업폴더를 만들어 목표·상태·로그를 기억하고, 규율대로 진행한다.

  • 작업폴더 work/<작업>/ 생성
  • 2팀+면 가동 게이트(동의)
  • 최소 팀 분배 · 검수 · 감사
  • 세션 끊기면 /madev:resume

작은 일은 가볍게, 큰 일은 규율대로 — 이 이중 구조가 madev의 핵심이다.
